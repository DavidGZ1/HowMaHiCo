# Project Style Guide

# R package + interactive HTML report + multi-tier distribution

# David Gomez-Zepeda — for use as context in new similar projects

------------------------------------------------------------------------

## Project architecture pattern

This style of project follows a layered architecture:

    LC-MS processed data (e.g., PEAKS CSV export, Fragpipe .tsv, DIA-NN .txt or p.parquet)
          │
          ▼
    R functions   — normalise, annotate, threshold, summarise
          │
          ▼
    Parameterised RMarkdown template (inst/rmarkdown/templates/)
          — produces a self-contained, interactive HTML report
          — all parameters declared in YAML header under params:
          — toggle static/interactive plots via params$PlotsInteractive
          │
          ▼
    Multiple csv files — incl. always-written input_params.csv (version + all params)
    Excel workbook   — summary tables via write.xlsx()

Distribution tiers (always provide all four, ordered easiest → most
powerful):

| Tier | Mechanism                    | Audience                           |
|------|------------------------------|------------------------------------|
| 1    | Windows `.bat` launcher      | Anyone, no coding, Windows         |
| 2    | Shiny browser app via Docker | Anyone, no coding, any OS          |
| 3    | Docker CLI                   | Intermediate, scripting/batch      |
| 4    | R package                    | Advanced, full programmatic access |

## R package conventions

### DESCRIPTION

- Use specific sub-packages, not meta-packages (`dplyr`, `tidyr`,
  `forcats` — not `tidyverse`)
- **Imports vs Suggests split**: packages used via `::` in `R/` files →
  Imports; packages only used inside the Rmd template → Suggests. Do not
  move Rmd-only packages into Imports (triggers “Namespaces in Imports
  not imported from” CI warning).
- Common Suggests for this pattern: `DT`, `openxlsx`, `plotly`,
  `scales`, `shiny`, `bslib`
- Common Imports: `dplyr`, `tidyr`, `forcats`, `ggplot2`, `rmarkdown`,
  `knitr`
- `knitr` goes in Imports (not Suggests) if used via `knitr::` in any
  `R/` file
- Bump version in both `DESCRIPTION` and `CLAUDE.md` when releasing

### NAMESPACE and man/ — never edit by hand

NAMESPACE and all `man/*.Rd` files are generated by roxygen2. The
correct workflow: 1. Fix `@param` tags in the `R/` source file 2. Run
`devtools::document()` to regenerate 3. After running, always check
`git status man/` — if fewer files changed than expected, run
`devtools::document()` again 4. Only commit once every relevant Rd file
is regenerated

### roxygen2 rules

- Every `@examples` block must be wrapped in `\dontrun{}` — **no
  exceptions**, even for pure functions. R CMD CHECK runs unwrapped
  examples and the package has no real instrument data in the check
  environment.
- `@param` tags must exactly match the function signature. Mismatches
  cause `Rd \usage sections` CI warnings (treated as errors).
- Add `@keywords internal` to suppress export from the pkgdown site
  without removing the export.
- Every new exported function must be added to `_pkgdown.yml` reference
  section in the same PR, or the pkgdown Action fails with
  `"topic missing from index: 'XYZ'"`.

### Coding patterns

- `%>%` pipe is re-exported by `dplyr` — no need to import separately
- No [`require()`](https://rdrr.io/r/base/library.html) calls inside
  functions — all dependencies declared in DESCRIPTION and imported via
  `@import` in a package-level file (e.g., `R/help.R`)
- Use `...` (dot-dot-dot) for flexible grouping arguments in summary
  functions — makes them reusable across different aggregation levels
  without code duplication
- `RiskLevel` and similar ordered factors: always use integer codes for
  computation/colour-scaling, labels for display; define the mapping as
  a named constant
- `replace_na(col, replace = 0)` on a column that could be all-NA: wrap
  with [`as.numeric()`](https://rdrr.io/r/base/numeric.html) first —
  otherwise R infers the column as `NA_logical_` and `replace_na`
  returns `FALSE` instead of `0`
- `replicate(n, expr, simplify = FALSE)` — first arg is count, second is
  expression (easy to swap)
- When replacing a deeply nested call with a simpler helper, recount
  closing parens — the nesting depth changes

### Tests (testthat edition 3)

- Tests live in `tests/testthat/`
- For functions that check `file.exists("relative/path")`: use
  `setwd(tmpdir)` + `on.exit(setwd(old_wd))` so the relative-path check
  hits the test-controlled directory, not the real CWD
- CI must pass with 0 errors, 0 warnings on both Windows and Ubuntu
  before merging to main

## Shiny app conventions

- UI:
  [`bslib::page_sidebar()`](https://rstudio.github.io/bslib/reference/page_sidebar.html)
  layout
- Theme:
  `bs_theme(primary = <brand_colour>, secondary = <accent_colour>)`
  matched to the package logo palette
- Logo: place in `inst/shiny/www/` — Shiny serves this directory as
  static assets automatically
- File output: always use `downloadHandler()` + `downloadButton()`.
  Never add a text input for a user-chosen output path — browsers cannot
  let a web server write to a user-selected local path (security
  constraint)
- The Shiny app is distributed as a separate Docker image (`:app` tag)
  extending the CLI image (`:latest`)
- `shiny` and `bslib` in Suggests, not Imports

### Shiny Docker image tag — critical

GHCR requires **all-lowercase** image names.
`${{ github.repository_owner }}` in GitHub Actions preserves mixed-case
(e.g., `DavidGZ1`). Always hardcode the lowercase tag in the workflow:

``` yaml
tags: ghcr.io/davidgz1/mypackage:app   # correct
tags: ghcr.io/${{ github.repository_owner }}/mypackage:app  # WRONG — will fail
```

## Docker conventions

### Base image and build

- Base: `rocker/r-ver:4.2.0` (or appropriate version)
- Use `renv::restore()` from `renv.lock` for reproducible dependency
  installs
- Three system-level requirements to add to `apt-get` on Ubuntu Focal:
  - `cmake` — required by nloptr
  - `libharfbuzz-dev libfribidi-dev` — required by textshaping/ragg
  - `pandoc` — not included in `rocker/r-ver` (unlike
    `rocker/tidyverse`); required for rmarkdown render
- Matrix version conflict: if renv.lock pins Matrix 1.4-1 but
  MatrixModels \>= 1.4-2 is needed, bump Matrix to 1.5-4.1 in renv.lock
  and drop the Hash field (renv recomputes it). Do not try to
  pre-install Matrix and use `exclude=` — renv’s sandboxed lib.loc
  doesn’t see the site-library.

### CLI entrypoint pattern

- `docker/entrypoint.sh` — bash script parsing `--flag value` args
- `docker/run_report.R` — called by entrypoint, invokes the main report
  function
- Expose all report parameters as CLI flags; document them in README
  with a table

### Windows usage gotchas

- Docker CLI not on PATH by default after Docker Desktop install. README
  and `.bat` launcher must address this.
- Volume mount maps a Windows path to a container path:
  `-v "C:\host\folder:/data"`. All file arguments must use the
  container-side path (`/data/file.csv`), not the Windows path.

## Windows `.bat` launcher rules

- **Never put a `:label` inside a parenthesised `if (...)` or
  `for (...)` block** — cmd.exe silently terminates the block at the
  label, causing unpredictable early exit. All labels must be at top
  scope; use `goto` to jump to them.
- All error paths must converge at a `:error_exit` label that always
  calls `pause` before `exit /b 1` — this keeps the window open so the
  user can read the error.
- Suppress Docker output with `>nul 2>&1` for daemon checks; show
  `docker pull` output so the user sees progress.
- Use `timeout /t N /nobreak >nul` for silent waits; never use `sleep`.
- Test with a double-click from Windows Explorer (not from a terminal) —
  the PATH and CWD may differ.

## Branch and release strategy

- `main` — stable releases only
- `dev` — integration branch; all work lands here first, then merges to
  main
- CI: R CMD CHECK on Windows + Ubuntu on every push/PR to both branches
- Merging to main triggers Docker image builds and pkgdown site
  deployment
- Version bumps: update `DESCRIPTION` (Version field) and `CLAUDE.md`
  (current version line) together
- GitHub Releases: tag as `vX.Y.Z`, attach the `.bat` launcher as a
  release asset so non-technical users have a direct download link
- The `releases/latest` URL in README always resolves to the newest
  release asset

------------------------------------------------------------------------

## pkgdown site

- Configured in `_pkgdown.yml`, deployed to GitHub Pages on push to main
- Every exported topic must appear in the `reference:` section —
  including the package-level help page (`man/PackageName.Rd`)
- To exclude a topic from the site: add `@keywords internal` to its
  roxygen block

------------------------------------------------------------------------

## CI checklist before merging to main

`devtools::check()` passes with 0 errors, 0 warnings

`git status man/` confirms all expected Rd files were regenerated

New exported functions added to `_pkgdown.yml`

Version bumped in DESCRIPTION and CLAUDE.md

Docker image tag is lowercase in workflow yaml

All `@examples` wrapped in `\dontrun{}`

Closing parens counted after any nested call refactor
